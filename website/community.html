02. Install the Community preview

# PyPI prerelease
python -m pip install --pre "lummenna[export]==1.0.1rc1"

# Or download and install the same wheel directly
curl --fail --show-error --silent --remote-name \
  https://lummenna.com/downloads/lummenna-1.0.1rc1-py3-none-any.whl
curl --fail --show-error --silent --remote-name \
  https://lummenna.com/downloads/SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS
python -m pip install "./lummenna-1.0.1rc1-py3-none-any.whl[export]"

The export extra is needed only to create the local ONNX embedding model. A node using an already-provisioned model can install the wheel without that extra.

03. Build the sidecar

The published Dockerfile pins the wheel by SHA-256 and refuses to build if the download differs. It also refuses to start without an API key.

curl --fail --show-error --silent --remote-name \
  https://lummenna.com/downloads/lummenna-community-1.0.1rc1.Dockerfile

docker build --pull \
  --file lummenna-community-1.0.1rc1.Dockerfile \
  --tag lummenna-community:1.0.1rc1 .

umask 077
printf 'LUMMENNA_API_KEY=%s\n' "$(openssl rand -hex 32)" > lummenna.env

04. Provision the model once

docker volume create lummenna-models

docker run --rm \
  --env-file lummenna.env \
  --env LUMMENNA_SOVEREIGN=false \
  --volume lummenna-models:/data/models \
  lummenna-community:1.0.1rc1 \
  lummenna model download bge-small-en-v1.5

This is the only required network-backed model operation. The model persists in the named volume and subsequent inference is local.

05. Run beside an agent

docker network create agent-memory
docker volume create lummenna-store

docker run --detach \
  --name lummenna \
  --restart unless-stopped \
  --network agent-memory \
  --env-file lummenna.env \
  --publish 127.0.0.1:8848:8848 \
  --volume lummenna-store:/data/store \
  --volume lummenna-models:/data/models \
  lummenna-community:1.0.1rc1

Attach the agent container to agent-memory and use http://lummenna:8848 as its memory API endpoint. Send the generated value from lummenna.env in the X-API-Key header on every /v1 request. The host binding remains loopback-only.

06. Release boundaries

This is a release candidate, not a stable release. It is single-node by design, the embedding model is not bundled, and the public Python API may change. Community use is governed by AGPL-3.0-or-later. Pro capabilities remain license-enforced.
