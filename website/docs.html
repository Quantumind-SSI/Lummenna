Community documentation / 1.0.1rc1

Prepare for first recall.

The Community release candidate is available from PyPI and directly from lummenna.com. Its Python API may change before the stable release.

01. Install the Community preview

Lummenna supports Python 3.10 through 3.12. Install the Community prerelease from PyPI; no source-control account is required.

python -m pip install --pre "lummenna[export]==1.0.1rc1"

Verify the package against SHA256SUMS, or use the complete Community sidecar guide.

02. Initialize the palace

lummenna init --device generic
LUMMENNA_SOVEREIGN=false lummenna model download bge-small-en-v1.5

The one-time model command downloads from Hugging Face and exports with the optional toolchain, so sovereign mode must be explicitly disabled for that command. Air-gapped installations must place a compatible model.onnx and tokenizer files under ~/.lummenna/models/bge-small-en-v1.5/ before isolation.

lummenna memory store "We chose SQLite for the cache layer" --room decisions
lummenna memory retrieve "cache layer"

03. Use it with curl

Start the server, then drive every operation over HTTP from any language or shell:

lummenna serve
# Observatory: http://localhost:8848/   API reference: http://localhost:8848/docs

Set an API key before exposing the server to any network, then authenticate every request with the X-API-Key header:

export LUMMENNA_API_KEY='replace-with-a-secret'

# Store a memory
curl -s -X POST http://localhost:8848/v1/store \
  -H "Content-Type: application/json" \
  -H "X-API-Key: $LUMMENNA_API_KEY" \
  -d '{"content": "Ship the release on Friday", "room": "decisions"}'

# Hybrid search (BM25 + dense + graph fusion)
curl -s -X POST http://localhost:8848/v1/search \
  -H "Content-Type: application/json" \
  -H "X-API-Key: $LUMMENNA_API_KEY" \
  -d '{"query": "release plans", "top_k": 5}'

# Retrieve and assemble a ready-to-use context block in one call
curl -s -X POST http://localhost:8848/v1/assemble \
  -H "Content-Type: application/json" \
  -H "X-API-Key: $LUMMENNA_API_KEY" \
  -d '{"query": "what should I remember about releases"}'

Other endpoints: GET /v1/status (palace overview), POST /v1/turn (store a full conversation turn), POST /v1/feedback (reinforce memories), and GET /v1/dashboard-data (tenant-scoped observatory data). The full machine schema is at /openapi.json. Without an API key the server refuses nothing on loopback, but any network exposure requires the key. Production startup requires a real local embedding model; LUMMENNA_ALLOW_MOCK_EMBEDDER=1 exists only for tests and UI development.

04. Connect an MCP client

The MCP server exposes seven tools: lummenna_search, lummenna_store, lummenna_assemble, lummenna_turn, lummenna_feedback, lummenna_status, and lummenna_dashboard. Spawn one server per client over stdio:

{
  "mcpServers": {
    "lummenna": {
      "command": "python",
      "args": ["-m", "lummenna.integrations.mcp_server"]
    }
  }
}

For several editor sessions at once, serve one shared process over Streamable HTTP instead of paying the ~750 MB embedder cost per client:

lummenna mcp --transport streamable-http --host 127.0.0.1 --port 8849
# Point every client at http://127.0.0.1:8849/mcp

Network MCP transports are a LAN exposure decision: they are unauthenticated by design, so keep them bound to loopback or a trusted interface behind the API key. Client-specific examples for Claude Desktop, Cline, Continue, Zed, Goose, and OpenCode exist in the repository's integrations/ directory for approved evaluators.

05. Use the Python API

from lummenna.config import LummennaConfig
from lummenna.data.schema import get_connection
from lummenna.force.mnemonic.store import store_memory

config = LummennaConfig()
conn = get_connection(config)
chunk_id = store_memory(
    conn,
    content="User prefers concise status updates",
    room_name="preferences",
    config=config,
)
conn.close()

LangChain and LangGraph adapters are optional extras. The REST API publishes its runtime schema at /openapi.json.

06. Build from source

Build the wheel and CLI binary from the source archive — no source-control account required. Clone or download the source, then build with the standard toolchain:

git clone https://github.com/Quantumind-SSI/Lummenna.git
cd Lummenna

python -m venv .venv && source .venv/bin/activate
python -m pip install --upgrade pip build
python -m build                    # produces dist/lummenna-1.0.1rc1-*.whl + tar.gz
python -m pip install "dist/lummenna-1.0.1rc1-py3-none-any.whl[export]"
lummenna --version                 # the binary entry point is now on PATH

To run straight from a checkout without building a wheel, install editable and invoke the CLI module directly: pip install -e ".[dev]" then python -m lummenna.cli.main serve. Verify any downloaded artifact against the published SHA-256 checksums before installing it.

07. Prepare production deliberately

Set an API key, choose an encryption mode where required, mount persistent storage and model volumes, and keep the service on loopback unless network access is intentional.

export LUMMENNA_API_KEY='replace-with-a-secret'
export LUMMENNA_DATABASE_ENCRYPTION_MODE='sqlcipher'
export LUMMENNA_ENCRYPTION_KEY='replace-with-a-separate-secret'
lummenna serve --host 127.0.0.1

Encryption-at-rest and non-default tenant isolation require a valid Pro entitlement. The deployment guide and security policy ship with the source; read both before exposing the API.
