Capability map / implemented code

Built to remember. Built to let go.

Capabilities are separated by edition and described at their implemented scope. Planned work stays on the roadmap rather than appearing here as an available feature.

01 / Core

The memory path.

The Community Edition includes the complete storage, retrieval, context, lifecycle, and server path.

01 / Structure

Memory palace

Rooms contain loci; loci and rooms organize chunks with provenance, temporal validity, and value metadata.

Community
02 / Search

Hybrid retrieval

BM25 through SQLite FTS5, dense vectors, graph traversal when available, and reciprocal rank fusion.

Community
03 / Prompt

Context assembly

Retrieved memories are formatted and reduced to an explicit token budget, including a defined emergency path.

Community
04 / Adapt

Twin-Force controller

A shared controller responds to retrieval interaction signals and exposes its current state to the observatory.

Community
05 / Retain

Three-layer lifecycle

Time decay, same-locus interference, and budget pressure govern value, precision, and eventual release.

Community
06 / Observe

API and dashboard

FastAPI endpoints, OpenAPI output, Prometheus metrics, and a dependency-free live observatory are implemented in the current code.

Community
07 / Encrypt

Encryption at rest

Licensed deployments can select SQLCipher whole-database encryption or Fernet field encryption.

Pro
08 / Isolate

Multi-tenant storage

Licensed non-default tenants are scoped through storage and retrieval paths with tenant-aware uniqueness.

Pro
09 / Govern

Compliance operations

Licensed safety-forgetting operations provide atomic erasure behavior and audit records at the implemented boundary.

Pro

02 / Observe

The running system, not a mockup.
